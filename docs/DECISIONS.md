# 技術選定と重要な判断

| # | 判断 | 理由 |
|---|---|---|
| 1 | **TypeScript + Node.js 22.13+、ビルド不要（tsx で直接実行）** | Windows で `npm ci` → `npm start` だけで動かすため。コンパイル成果物の管理を不要にした |
| 2 | **DB は Node 組み込みの `node:sqlite`** | better-sqlite3 等のネイティブモジュールは Windows でビルド失敗の原因になる。1 ファイルで永続化・バックアップが容易。実験的機能の警告は起動時に抑制 |
| 3 | **Web は Hono によるサーバー描画、管理画面の JavaScript なし** | 依存と攻撃面を最小化。CSP で `script-src 'none'`。自動更新は `<meta refresh>` |
| 4 | **スクリーンショットは playwright-core ＋ PC 既存の Edge/Chrome** | ブラウザのダウンロード不要。Windows 11 は Edge 標準搭載。ブラウザがない場合は該当項目を「未確認」にして処理は継続 |
| 5 | **Docker / WSL は不要** | 通常の Windows 環境で起動できる構成を優先 |
| 6 | **AI なしで主要フローが完結**（分析＝ルール、モック・営業文＝テンプレート） | 費用ゼロで検証でき、出力の根拠が追跡可能。AI は営業文の推敲のみ任意で使用 |
| 7 | **AI は Codex CLI（ChatGPT ログイン）、`codex exec --sandbox read-only`、プロンプトは標準入力** | 要件（既存 ChatGPT ログインを優先、Claude 非依存）。API キーは子プロセスに渡さず従量課金へ自動切替しない。毎回送信内容を表示して同意を得る |
| 8 | **送信は模擬送信＋EML 出力のみ** | 要件「最初は模擬送信で検証」。実送信は設定・接続先・内容の承認後に実装する |
| 9 | **承認は内容ハッシュに紐づけ、72 時間で失効** | 宛先・本文・プレビュー・営業可否・配信停止が変われば自動で無効。表示時のハッシュと一致しない承認要求は拒否 |
| 10 | **営業可否の「送信可」は人だけが根拠付きで設定** | 「メール公開だけで送信可と判断しない」要件。特定電子メール法第3条第1項第4号の例外（公表アドレス・拒否表示なし）に該当するかは利用者が確認・記録 |
| 11 | **架空企業は予約 TLD `.example` の固定サイト** | ネットワーク通信なしで検証でき、SSRF 対策にテスト用の抜け穴を作らずに済む |
| 12 | **公式サイトの自動確認は「ドメイン一致＋ページ内に企業名」のみ** | 推測 URL を公式として確定しないため。それ以外は「HTTP応答あり・公式性未確認」として人が確定 |
| 13 | **モックは業種テンプレート×ブランド色×観察事実×レイアウト変化** | 企業名の置換だけにしない。サイトの文章は転載せず、事実（サービス名・地域・アクセス）から新しい文を作る。実績欄は「掲載予定領域」。歯科は医療広告ガイドラインに配慮し体験談枠を作らない |
| 14 | **画像は使わず独自の SVG 図形** | 権利不明の素材を使わない。素材の出典をモック仕様に記録 |
| 15 | **プレビューはランダム 192bit トークン＋8 桁閲覧コード＋期限＋失効、noindex 三重対策** | 管理画面とは別の認可（HMAC 署名 Cookie、パス限定） |
| 16 | **ジョブは SQLite の永続キュー。送信はジョブ化しない** | 再起動で処理中を待機に戻して再開。送信は利用者操作のみなので再実行で重複送信が起きない |
| 17 | **Google Places API は不採用** | Places のコンテンツは place_id 以外の保存・キャッシュが制限され、営業リストとして保存する用途に適さない |
| 18 | **gBizINFO はアダプターのみ実装（トークン待ち）** | 無料だが利用申請が必要。公式サイト URL を含まない場合は除外し補完を人に委ねる |
